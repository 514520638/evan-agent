| 模型接入 | Python 项目、MiniMax Anthropic 兼容接口、env 配置 | 聊天订阅与 API 授权不同；模型返回的自我介绍不能证明真实型号 |

| 个人资料 | SQLite 原文、分类、来源、公开状态 | 数据权威来源、CRUD、权限先于检索 |
| 记忆审批 | 本人自然语言写入、HITL、补充表单 | interrupt/checkpoint/resume，显式确认与幂等意识 |
| API 与博客 | FastAPI、HttpOnly Cookie、fetch SSE | 前后端协议、跨域与 CSRF 边界、增量渲染 |
| 持久化 | 聊天、令牌、审批草稿、回执 | 崩溃恢复、单进程锁、已提交写入不能盲目重试 |
| RAG | chunk、bge-m3、向量缓存、BM25/RRF/MMR | 语义召回与生成是两种不同能力 |
| 质量评估 | 真实资料、多轮问答、规则评分、人工复核 | 评分器也会误判；高规则分数不等于全部事实正确 |
| 知识管理 UI | 本人表单管理原文和状态 | 显式保存、删除确认、过期登录、资料版本失效 |

| 清理 | 访客 1 小时、审计 183 天、模型变更清向量 | 数据生命周期、运行任务收尾与过期访问分离 |
| 上线 | Docker amd64、Nginx、完整数据迁移、dist 更新 | 容器架构、端口监听、数据卷、入口文件最后发布 |

## 前端知识点

React 18 组件与 Hooks 管理聊天状态；React Router 组织页面；Redux Toolkit 管理博客业务数据；
Ant Design 提供表单、抽屉和状态反馈；i18next 与 useLanguage 支持语言切换；Markdown 渲染用于文章和回答。
AgentChat 挂载在全站 Layout，KnowledgePanel 仅本人角色显示；隐藏按钮不能替代后端授权。
api/agent.ts 使用同域 /agent-api、credentials=include 和 X-Agent-Request，解析 POST SSE。
API 中的 message_start/delta/done、approval_required、search_status、error 是前后端需要共同维护的协议。

## Java 后端知识点

Spring Boot Controller 做 HTTP 边界，Service 承载业务，JPA Repository 负责查询，Entity 映射 MySQL。
文章有分类与标签关联，发布/删除状态与真正物理删除应区分；相册数据库保存元信息，图片文件需单独备份。
博客管理员服务和 Agent 的身份体系不同，跨服务统一登录属于未来设计，不能直接共享某个密码字段。
默认配置凭据、简历记录中的 password 字段是需专项复查的点，不在文档中展示真实值。

## Agent 知识点

- Tool calling：模型决定何时调用，程序执行工具并提供结果；最终权限判断由程序负责。
- 短期记忆：当前聊天上下文与摘要；长期记忆：经确认保存的资料，而非每句话都自动落库。
- Embedding：文本到数值向量；MiniMax 负责生成回答，bge-m3 负责相似性检索。
- RRF：融合不同检索排序，避免直接相加量纲不同的分数；MMR：降低冗余，不是神经重排。
- Human-in-the-loop：暂停等待人类决策，checkpoint 保留恢复位置；审批不是模型自行确认。
- Stream：回答逐步到达，连接断开不代表服务器操作回滚；重新读取回执优于自动重发。
- 可观测性：日志描述调用与耗时；不能将主模型 token 统计当作含搜索子调用的完整账单。

## 日常开发顺序

1. 明确需求、角色权限、数据归属、失败场景和验收标准。
2. 先修改存储/服务与 API 契约，再接前端；更新数据结构时计划迁移与回滚。
3. 对权限、状态恢复、外部接口适配做有意义的测试；对真实检索做有限真实评估。
4. 构建前端、检查 diff，确认 .env 与数据不进入镜像。
5. 版本化构建 amd64 镜像，冷备份，更新服务，再发布前端入口。
6. 记录真实域名验收结果与资源曲线，持续观察，出现问题回滚对应组件。

## 评估方法与限制

评估分检索与答案：正确片段是否进入 Top3；核心事实是否齐全；是否扩写；引用是否能支持句子；是否越权写入。
固定集适合回归，另外保留陌生问法做验收。未知问题应明确没有资料，不将推测当事实。
当前 evals 规则主要使用正则和来源 ID，可能误判否定表达、遗漏新型幻觉，也不验证每个引用的语义支撑。
现有 summarize 对调用错误单独统计，答案分母只含有答案的行；看准确率时必须同时看 errors。
教育题目前要求包含本科，问题仅问院校时正确但简短的答案也可能被判失败，需人工审阅规则合理性。
这些是现有评估器的能力边界，不应把规则评分包装为统计保证。

## 下一阶段优先级

1. 完成线上聊天、登录、审批恢复、私密隔离、长时间内存观察的验收记录。
2. 配置并验证异机备份、恢复与告警，而不是仅依靠健康检查。
3. 充实真实项目资料，让简历/项目问答有可靠证据。
4. 改善评估数据与引用核对；数据变大后再升级索引和历史分页。
5. 规划宿主机系统迁移、数据库网络收敛及 Java 认证配置专项复查。
