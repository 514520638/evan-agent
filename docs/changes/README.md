# 紧凑变更记录

每个修改任务一份 `<稳定key>.json`，由 `scripts/workflow.py intake` 创建。
请求、范围、AC、决定、缺口、下一步、实现结果、验证和用户验收保存在同一文件。
新记录为 v2：AC 带来源、测试 ID／人工方法及逐项验证；返工通过 `rework` 在同一文件保存修订历史。
新任务通过 align 采用可选 protocol v1 扩展，保存授权边界、请求事件、生命周期、最小方案和故事线引用；旧任务继续开发时按原授权对齐，不批量迁移。
协议任务 resume 默认当前摘要；完整历史使用 --full。基础 Python API resume 仍返回原始记录。
完整测试详情和起始文件哈希基线留在忽略的 `.workflow/`，记录只保留映射用例和未通过用例的详情。
v1 历史记录继续可读；重新修改或验证时升级并清除旧证据，不批量改写历史。
只读分析不建记录，不把提示词全文、密钥、个人资料或日志复制到这里。

记录可随代码提交，结果以实际命令为准；自动检查不能推导用户已经验收。
示例使用方法和字段约束见 `../DEVELOPMENT.md`，无需为短任务另建需求与计划文档。
故事线、经验和渐进上下文的命令见 [协议文档](../WORKFLOW_PROTOCOL.md)。
